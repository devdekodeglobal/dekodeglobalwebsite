krafc
2D Architectural Drafting & Real-Time 3D Spatial WebGL Engine

Millimeter-accurate 2D blueprint drafting (HTML5 Canvas via Konva) synchronized in real-time with instant photorealistic 3D WebGL spatial simulation (BabylonJS 9.x), backed by an edge-native Cloudflare Pages & D1 serverless backend.

What krafc Solves

Traditional exhibition stall and interior design workflows force designers between clunky 3D CAD software (Blender, AutoCAD, 3ds Max) with steep learning curves, and flat 2D tools with zero real-time visualization. krafc provides instant bidirectional 2D ↔ 3D synchronization directly inside any web browser.

Architectural Rule: Canonical Coordinate Contract

The 2D canvas strictly adopts a PPM = 100 scale (100 pixels = 1.00 metre). The 3D Babylon engine projects X → X (meters), Z → -Y (meters, inverted depth), and Y → Z (elevation/height). No visual element escapes this coordinate mapping contract.

Product Vision, Market Context & Core Philosophy

Exhibition booth design, interior space planning, and commercial retail fit-outs represent multi-billion-dollar industries plagued by fragmented toolchains. A typical workflow involves an architect sketching in AutoCAD, sending blueprints to a 3D visualizer working in 3ds Max / V-Ray, waiting hours for offline renders, sending drafts back to clients, and manually hand-compiling Bills of Materials (BOM) in Excel.

Zero-Install Fluidity

Runs entirely inside any modern browser on desktop or tablet. No heavy CAD licenses, no GPU workstation requirements, and zero client installation required.

Real-Time Split Visualization

Instant dual-view workspace: edits made on the 2D blueprint (moving walls, placing furniture, resizing counters) immediately reflect in the real-time 3D viewport with dynamic PBR lighting and shadows.

Automated Executive BOM

Generates print-ready technical schematics, exact spatial coordinate manifests, furniture schedules, and procurement bills of materials with a single click.

Design Philosophy: "What You Draw Is What You Walk Through"
krafc eliminates mental coordinate translation. The 2D blueprint is not an abstract schematic; it is the real-time mathematical source of truth for the physical 3D world.

Dual-Engine Architecture: 2D ↔ 3D Synchronization

At the heart of krafc lies a decoupled dual-engine pipeline. The state lives in a centralized React tree (managed in src/routes/editor.tsx) with persistent synchronization to both the 2D Konva canvas and the BabylonJS 3D engine.

2D Canvas Engine (Konva)

  • Renderer: HTML5 Canvas 2D Context via react-konva
  • Coordinate Space: Canvas Pixels (Screen Space)
  • Scale: PPM = 100 (100 px = 1 meter)
  • Interaction: Snapping grid, draggable transformer bounds, multi-point polygon manipulators
  • File: src/components/editor/Canvas.tsx

3D Spatial Engine (BabylonJS 9.x)

  • Renderer: WebGL 2.0 / WebGPU via @babylonjs/core
  • Coordinate Space: Metric World Space (X, Y, Z in meters)
  • Lighting: Hemispheric ambient + Cascaded Directional Light with real-time soft shadows
  • Geometry: Custom procedural extrusions, Earcut polygon tessellation, GLTF/GLB/DAE mesh loader

Spatial Math, Units & Canonical Coordinate Contracts

A fundamental source of bugs in spatial software is mixed coordinate conventions. krafc enforces strict mathematical rules across the codebase:

Dimension 2D Konva Space (Pixels) 3D BabylonJS Space (Meters) Mathematical Conversion
Horizontal (Width) x (px, 0 at top-left / center) position.x (meters, world center at 0) x_3d = (x_2d - totalWidthPx/2) / 100
Depth (Floor depth) y (px, increasing downwards) position.z (meters, depth axis) z_3d = -(y_2d - totalDepthPx/2) / 100
Elevation (Height) N/A (Layer order / zIndex) position.y (meters, ground at y = 0) y_3d = (element.elevation || 0) + height/2
Rotation rotation (degrees, clockwise) rotation.y (radians, counter-clockwise) rot_3d = -degToRad(rotation_2d)

Key Invariant: Pixels Per Metre (PPM)

export const PPM = 100; // 100 pixels represents exactly 1.00 physical metre

export function pxToMeters(px: number): number {
return Number((px / PPM).toFixed(3));
}

export function metersToPx(meters: number): number {
return Math.round(meters * PPM);
}

Room Shapes, Wall Topology & Procedural Boundaries

Unlike naive rectangular floor planners, krafc supports parametric geometric room shapes managed by src/lib/roomShapes.ts:

Rectangle / Square

4 Cardinal boundary edges (North, South, East, West). Support for independent wall disabling to create open-front exhibition booths.

L-Shaped Plan

6-vertex concave polygon with parametric notch width (lNotchWidth) and depth (lNotchDepth). Computes interior corner normals.

Regular Polygons & Circles

Triangles, Pentagons, Hexagons, and N-segment regular circular polygons (configurable tessellation: 8 to 64 facets).

Earcut Polygon Floor Triangulation

BabylonJS utilizes the earcut library to triangulate concave and multi-point 2D room outlines into 3D index-buffer geometry: 

// Triangulating arbitrary room polygons into 3D floor geometry:
const shapeCorners = pts.map(p => new BABYLON.Vector3(p.x, 0, -p.y));
const floorMesh = BABYLON.MeshBuilder.CreatePolygon("roomFloor", {
shape: shapeCorners,
sideOrientation: BABYLON.Mesh.DOUBLESIDE,
updatable: true
}, scene, earcut);

Client-Side IndexedDB & Offline Asset Storage

To support high-bandwidth 3D workflows without crushing network bandwidth or requiring constant cloud sync, krafc implements a client-side persistent storage subsystem in src/lib/customAssetDB.ts:

IndexedDB Asset Cache

Stores binary 3D model files (GLTF/GLB/DAE), wall graphic high-res textures, and custom uploaded SVG logos locally on the user's machine.

Zero-Loss LocalStorage

Automatic draft autosave on every transform event. If the browser tab crashes or refreshes, the active stall design is restored instantly from local storage.

LRU In-Memory Image Cache

Managed in src/lib/imageCache.ts, preloads and pools texture canvases to prevent garbage collection pauses during real-time 3D navigation.

Cloudflare Pages Functions & D1 Database Schema

The backend is 100% serverless, running as Cloudflare Pages Functions in V8 isolates across Cloudflare's global edge network. The primary database is Cloudflare D1 (distributed SQLite):

Table Name Primary Key Purpose & Description
users id (TEXT, 32-char hex) User accounts, email, display name, PBKDF2 password hash, Google OAuth ID, verification status.
sessions id (TEXT, 32-char hex) Active user login sessions, cookie-bound, with 30-day ISO timestamp expirations.
projects id (TEXT, 32-char hex) Parent folders/projects grouping related designs and client spaces.
designs id (TEXT, 32-char hex) Spatial blueprints: contains JSON room config, JSON elements array, metadata, timestamps.
security_limits id (TEXT) Edge-native IP and user rate limiting counters with automatic timestamp resets.
registration_challenges email (TEXT) Pending user sign-ups: holds SHA-256 hashed 6-digit OTP codes and expiration timestamps.
oauth_challenges id (TEXT) PKCE verifier tokens for Google OAuth authorization handshakes.

Authentication, Cryptographic Standards & Security Gates

Built in functions/_auth-utils.ts, the security model meets enterprise-grade specifications:

PBKDF2 Password Hashing (Web Crypto API)

Passwords are never stored in plaintext or legacy weak hashes. We employ native Web Crypto PBKDF2:

  • Iterations: 100,000 rounds
  • Salt: 16 cryptographically random bytes via crypto.getRandomValues
  • Digest: HMAC-SHA256 producing a 256-bit derived key
  • Format: pbkdf2:100000:{saltHex}:{hashHex}
  • Timing Attacks: Constant-time string equality validation (timingSafeEqual)

Session & Cookie Security

Authentication cookies strictly enforce production defense-in-depth flags: 

HttpOnly; Secure; SameSite=Lax; Max-Age=2592000; Path=/

Prevents cross-site scripting (XSS) extraction while ensuring secure transmission over HTTPS.

Zero-Trust Payload Validation & DoS Defense Budgets

In shared/validation.ts, all untrusted inputs submitted to API endpoints undergo recursive budget parsing to stop denial-of-service (DoS) and prototype pollution attacks:

Tree Budget Limit

Max recursive depth: 12 levels.
Max AST node count: 20,000 nodes.
Rejects deeply nested malicious JSON payloads before deserialization locks the thread.

Prototype Pollution Defense

Rejects any payload property key matching __proto__, constructor, or prototype, or keys exceeding 80 characters in length.

Design Size & Element Limits

Max raw design payload: 1 MiB (1,048,576 bytes).
Max element count: 500 items.
Coordinates constrained to physical bounds (0 , 100 metres).

# Install dependencies

npx wrangler pages dev dist --d1 DB=krafc-local-db

Developer Recipe: Adding a New 3D Asset to the Catalog

Follow this standardized 3-step checklist to introduce a new furniture piece or architectural structure to the catalog:

Step 1: Place 3D Model in Public Directory

Save optimized .glb, .gltf, or .dae files into public/models/{category}/{asset-id}/. Ensure polygon count is under 25,000 triangles and textures are compressed (PNG/WebP, max 2048x2048).

Step 2: Register in Asset Catalog (src/lib/assetRegistry.ts)

{
id: "nordic-lounge-chair",
category: "chairs",
categoryFolder: "chairs",
label: "Nordic Lounge Chair",
details: "Width: 78 cm; Depth: 82 cm; Height: 85 cm; Oak frame, linen upholstery",
w: 1, 
h: 0.9512,
specW: 0.78, // Meters in 3D
specD: 0.82, // Meters in 3D
specH: 0.85, // Meters in 3D
facingOffset: 0 // Optional angular rotation offset
}

Step 3: Define 2D Architectural Symbol (ArchitecturalSymbol2D.tsx)

Map the asset ID to its 2D CAD representation so it renders legibly on the blueprint and in exported technical PDF reports.

Developer Recipe: Adding a Secure Cloudflare API Endpoint

Creating a new serverless function under functions/api/: 

import { getSessionId, getSessionUser, json, jsonError } from '../../_auth-utils';
import { object, boundedTree, HttpError } from '../../../shared/validation';

interface Env {
DB: D1Database;
}

export const onRequestPost: PagesFunction<Env> = async ({ request, env }) => {
// 1. Authenticate user
const sessionId = getSessionId(request);
const user = await getSessionUser(env.DB, sessionId || '');
if (!user) return jsonError('Unauthorized', 401);

// 2. Parse & validate payload within DoS budget
let body: unknown;
try {
body = await request.json();
boundedTree(body); // Limit recursion and AST depth
} catch {
return jsonError('Invalid payload', 400);
}

// 3. Execute parameterized SQL query
const { results } = await env.DB.prepare(
'SELECT * FROM designs WHERE user_id = ? ORDER BY updated_at DESC'
).bind(user.id).all();

// 4. Return secure JSON response
return json({ success: true, data: results });
};

Production Deployment & Cloudflare Runbook

Deploying changes to the global edge network:

Production Deployment Command

  1. Run npm test to ensure all cryptographic and unit tests pass.
  2. Run npm run build to verify TypeScript compiler checks and zero bundle warnings.
  3. Ensure database migrations in migrations/ have been executed on the production D1 instance if schema changes were introduced.
  4. Verify production environmental variables (Resend API key, Google OAuth Client Secrets) in Cloudflare Pages dashboard.
