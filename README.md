# DEKODE Conversational Experience

This Vite/React application contains the existing DEKODE text conversation plus an optional, isolated real-time browser voice layer called **DEKODE Voice**.

## Architecture & Hosting

This project is built as a highly interactive Single Page Application (SPA) powered by Vite and React, heavily integrated with conversational AI. 

The application is deployed to **Cloudflare Pages**. 
> **Important:** Because the proposal security gateway relies on native cryptographic functions (like `pbkdf2`), you must enable the **`nodejs_compat`** compatibility flag in your Cloudflare Pages project settings (Settings > Functions > Compatibility Flags).

The backend API runs as Cloudflare Pages Functions (configured via `scripts/prepare-sites-build.mjs`).

## DEKODE Voice Architecture

The integration point is `src/components/ChatApp.jsx`. With voice enabled, the existing microphone position opens `DekodeVoiceSession`; with voice disabled, the original speech-input handler and all existing text-chat behaviour remain in place. Completed voice turns are appended through the same `messages` collection, and voice knowledge responses are passed into the existing `CompanyKnowledgePanel`.

The implementation is separated into:
- `src/components/voice`: permission, listening, thinking, speaking, transcript, interruption, meeting preference, end state, and editable lead-review UI.
- `src/voice`: feature configuration, analytics allow-list, session state model, browser speech providers, intent classification, knowledge-grounded conversation, and lead qualification.
- `src/meetings`: replaceable meeting provider contract, dynamic mock provider, and calendar-provider placeholder.
- `src/leads`: editable form generation, validation, sanitised payload preparation, and mock/server notification adapter.
- `src/consent`: explicit consent state helpers.
- `api/leads.js` and the Cloudflare Pages worker generated by `scripts/prepare-sites-build.mjs`: server-side validation/sanitisation boundaries with truthful mock delivery.

Browser `SpeechRecognition`/`webkitSpeechRecognition` and `speechSynthesis` are development fallbacks, not a production realtime voice provider. If recognition is unavailable or permission is denied, the same voice session remains usable through its text field. Raw audio is not permanently stored.

## Configuration

Copy `.env.example` to `.env` or `.env.local` when local overrides are needed. 

> **Warning:** All `VITE_*` values are public client configuration. **Never** place a voice, AI, email, CRM, or calendar secret in a variable that starts with `VITE_`.

```env
# General / Vite Settings (Public - OK for browser)
VITE_DEKODE_VOICE_ENABLED=false
VITE_VOICE_PROVIDER=browser
VITE_VOICE_FALLBACK_ENABLED=true
VITE_MOCK_MEETING_SLOTS_ENABLED=false
VITE_COMPANY_TIMEZONE=Asia/Kolkata
VITE_LEAD_NOTIFICATION_MODE=live
VITE_LEAD_NOTIFICATION_ENDPOINT=/api/leads
VITE_CLIENT_PROPOSALS_ENABLED=true
VITE_PROPOSAL_CHAT_ENABLED=true
VITE_PROPOSAL_ACCESS_MODE=password_only
VITE_MEETING_PROVIDER=calendar
```

## AI Configuration (Google Gemini)

The application utilizes Google's Gemini models for intent classification and knowledge-grounded conversation. These are server-only secrets and must be added to your Cloudflare Pages environment variables (for both Production and Preview environments).

```env
GEMINI_API_KEY=your_primary_key
GEMINI_API_KEY_2=your_fallback_key
GEMINI_API_KEY_3=your_tertiary_key
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_FALLBACK_MODEL=gemini-3.5-flash
```

## SEO & Indexing

Because the interface is heavily chat-driven, we employ a custom build-time SEO architecture so search engines can crawl the site without executing chat flows.
During `npm run build`, the `scripts/inject-seo-content.mjs` script automatically reads the corporate knowledge from `companyKnowledge.json` and injects it as a visually hidden, semantically structured `<noscript>` and HTML block into `dist/client/index.html`. 
Coupled with JSON-LD structured data and a static `sitemap.xml`, this ensures flawless indexing of capabilities and case studies.

## Protected Client Proposals

The client-proposal feature is isolated behind `VITE_CLIENT_PROPOSALS_ENABLED`.
Approved proposal source is stored under `api/_proposal/source`, verified by SHA-256, and converted into server-only response payloads during the build.

Production requires a long, random `PROPOSAL_SESSION_SECRET` server variable. Proposal access creates a signed, expiring, HTTP-only cookie scoped to one proposal. Protected content, assets, and proposal chat reject requests without that session and return private/no-store/noindex headers.

## Google Calendar Booking

The text and voice experiences share the same server-side Google Calendar integration. The browser requests safe availability data from `/api/calendar/availability`; `/api/calendar/book` rechecks the selected time before creating an event, Google Meet link, and attendee invitation.

Set these server-only values in Cloudflare Pages and `.env.local`:

```env
GOOGLE_CALENDAR_ID=contactus@dekodeglobal.com
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REFRESH_TOKEN=
GOOGLE_CALENDAR_TIMEZONE=Asia/Kolkata
GOOGLE_CALENDAR_WORKDAY_START=09:00
GOOGLE_CALENDAR_WORKDAY_END=17:00
GOOGLE_CALENDAR_MEETING_DURATION_MINUTES=30
GOOGLE_CALENDAR_BUFFER_MINUTES=15
GOOGLE_CALENDAR_MINIMUM_NOTICE_HOURS=24
```

Enable the Google Calendar API in the Google Cloud project and generate the refresh token while signed in with a Google Calendar OAuth scope. Keep all four `GOOGLE_*` credentials server-side.

## Lead Delivery

The default `mock` mode validates and prepares a request but does not send email, create a CRM record, or book a meeting. 
To add real delivery, connect mail (e.g. SMTP) or CRM services inside the API handlers, store credentials only on the server, and return `delivered: true` only after the external service confirms success.

## Development and Verification

```bash
npm install
npm run dev
npm test
npm run lint
npm run build
```

`npm run dev` includes a development-only bridge for the existing `/api` handlers.
`npm run build` regenerates `src/knowledge/companyKnowledge.json`, compiles the Vite frontend, prepares the Cloudflare worker (`prepare-sites-build.mjs`), and finally injects the semantic SEO layer (`inject-seo-content.mjs`). Voice and text therefore use the same knowledge bundle loaded once at runtime.
